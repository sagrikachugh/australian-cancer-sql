Personal SQL project

Exploring Australian cancer data with SQL

I mainly work in R, so I built this project to develop practical SQL skills using a real Australian public-health dataset. The analysis covers national cancer incidence and mortality data published by the Australian Institute of Health and Welfare (AIHW).

Why I built it

I wanted to learn SQL by using it in a complete analysis rather than working through isolated exercises. My aim was to practise joins, common table expressions, parameterised queries and window functions while still applying the reproducibility and data-quality habits I use in R.

I chose cancer statistics because the source data are substantive enough to require careful definitions. Incidence and mortality do not always use identical cancer groupings, and recent published values include projections. Those details affected how I designed the tables and queries.

What I did

  1. Prepared the source data. I downloaded two AIHW Excel workbooks and standardised their fields in R.
  2. Built the database. I loaded incidence, mortality and cancer-definition tables into DuckDB with explicit data types and keys.
  3. Wrote six analyses in SQL. They cover rankings, trends, incidence-to-mortality comparisons, year-on-year change and age profiles.
  4. Added data-quality checks. Five SQL queries test for duplicates, missing values, missing years, implausible values and unmatched cancer codes.
  5. Tested and reported the results. R tests check the query outputs before Quarto renders the reports and charts.

A SQL example

This query calculates annual change in the published age-standardised incidence rate. I used LAG() to access the previous year without collapsing the annual rows.

WITH lagged AS (
  SELECT
    year,
    sex,
    asr,
    is_projection,
    LAG(asr) OVER (
      PARTITION BY cancer_code, sex
      ORDER BY year
    ) AS previous_asr
  FROM incidence
  WHERE cancer_code = ?
    AND age_group = 'All ages'
)
SELECT
  year,
  sex,
  asr,
  previous_asr,
  asr - previous_asr AS absolute_change,
  100.0 * (asr - previous_asr)
    / NULLIF(previous_asr, 0) AS percentage_change,
  is_projection
FROM lagged
ORDER BY sex, year;

The ? is a bound parameter supplied through R's DBI interface. NULLIF() prevents division by zero.

What I learned

Coming from R, I found common table expressions relatively intuitive because they resemble creating intermediate data frames. Window functions took more adjustment: they calculate across related rows while preserving the original row-level result, unlike a grouped summary.

I also found that defining the analytical grain early made the queries easier to reason about. In this project, that meant being explicit about cancer type, sex, age group, year and whether a value was observed or projected.

Limitations

  • The data are national aggregates, not patient-level or state-level records.
  • Incidence is observed through 2021 and projected for 2022–2025; mortality is observed through 2023 and projected for 2024–2025.
  • Several cancer groups use different ICD-10 definitions in the incidence and mortality workbooks. I exclude those groups from direct incidence-to-mortality ratios.
  • Age-standardised rates are taken from AIHW; this project does not recalculate them.
  • Published values may change in later AIHW releases.
